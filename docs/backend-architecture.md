# Hamyon — архитектура бэкенда

Версия 1, 4 октября 2026. Описывает сервер для общих счетов, долгов между людьми, профиля и
уведомлений друзьям. Кода пока нет.

## 1. Что делает сервер и чего на нём нет

Сервер нужен только для того, что происходит **между людьми**:

- профиль — чтобы друзья видели, кто вы и куда вам переводить;
- общие счета («Ужин в Beshqozon: ваша доля 47 000 сум»);
- долги, которые видят обе стороны, и подтверждение возвратов;
- уведомления другим людям.

На сервер **никогда не попадают**: SMS, операции, остатки, бюджеты, анализ ИИ, ваши карты (кроме тех,
что вы сами укажете «для переводов мне»). Приложение работает как сейчас — без аккаунта и без сети.
Вход нужен только для функций с друзьями.

## 2. Главное ограничение: у друзей может не быть приложения

Пока нет платного Apple Developer Program (99 $/год), друзья не могут нормально поставить Hamyon, а сервер
не может слать им пуши. Поэтому каждая общая вещь должна работать **без приложения у второй стороны**:

| Кто | Что у него есть | Что он может |
|---|---|---|
| **Контакт** | только имя (и, может быть, телефон) в вашем счёте | ничего — вы пересылаете ему ссылку сами |
| **Гость** | открыл ссылку или нажал Start в Telegram-боте | видит свою долю и карту, жмёт «Я перевёл», получает напоминания в Telegram |
| **Пользователь** | Hamyon с входом | всё то же в приложении + автосверка по SMS |

Если платный аккаунт появится, добавится только канал APNs и вход через Apple (этап 4) — модель данных не меняется.

## 3. Стек и размещение

Тот же стек, что у QRTifact, — уже знаком и развёрнут:

- FastAPI, Python 3.12, SQLAlchemy 2 (async, asyncpg), Alembic, Pydantic v2;
- PostgreSQL 16, Redis 7 (коды входа, лимиты, кэш);
- Celery + beat: отправка уведомлений, напоминания по срокам;
- aiogram 3 — Telegram-бот в режиме webhook внутри API;
- Jinja2 — страницы счёта для друзей без приложения;
- Docker Compose на том же сервере Timeweb за тем же Traefik, **отдельный** compose-проект и отдельная база;
- GitHub Actions: тесты → деплой, как в QRTifact.

Отдельный репозиторий `hamyon-api`. Правила кода — как в QRTifact: route → service → model, только async,
`AppException`, атомарные обновления счётчиков, UUID-ключи.

Нужны домен (например `hamyon.uz`: `api.` — API, корень — страницы счетов) и бот через BotFather.

> Перед публичным запуском: закон РУз «О персональных данных» требует хранить персональные данные граждан
> Узбекистана на серверах в Узбекистане. Для круга друзей это не важно, перед запуском для всех — проверить
> с юристом, переехать в местный ЦОД и зарегистрировать базу.

## 4. Вход через Telegram

Бесплатно, подтверждает номер телефона и сразу даёт канал для уведомлений.

1. Приложение: `POST /auth/telegram` → `{login_id, poll_token, bot_url}`, где `bot_url = t.me/<бот>?start=login_<login_id>`.
   `login_id` — 128 бит, живёт 10 минут в Redis. `poll_token` есть только у приложения: кто увидел ссылку
   на бота, токены всё равно не заберёт.
2. Приложение открывает Telegram, человек жмёт Start.
3. Бот просит «Поделиться номером» (кнопка `request_contact`). Проверяем `contact.user_id == from.id` —
   номер свой, а не чужой из контактов.
4. Сервер находит или создаёт пользователя по телефону, привязывает `telegram_id`, отмечает `login_id` как
   подтверждённый. Бот отвечает «Готово, вернитесь в Hamyon».
5. Приложение опрашивает `GET /auth/telegram/{login_id}` (каждые 2 с и при возврате в приложение) и получает токены.

При повторном входе с уже привязанным Telegram бот спрашивает «Войти в Hamyon на «iPhone»?» — [Войти] [Это не я],
без номера. Подсказка «нажимайте, только если вы сами сейчас входите» — от подсунутой чужой ссылки на вход.

Токены:

- access — JWT на 30 минут;
- refresh — случайные 256 бит, в базе только хэш, **меняется при каждом обновлении**. Повторное использование
  старого refresh → сессия отзывается (кража токена);
- хранятся в Keychain.

`DELETE /me` удаляет аккаунт — App Store требует удаления, если есть регистрация.

Другие способы входа и почему не сейчас: SMS-код (Eskiz) — платно за каждое SMS и нужен договор;
вход через Apple — только с платным аккаунтом (этап 4); Telegram Gateway — платно за код.

## 5. Данные

Все ключи — UUID. Для счетов и долгов **UUID создаёт приложение**: повторная отправка того же запроса
(плохая сеть) не создаёт дубль.

```
users            id, phone (E.164, uniq), name, avatar_url, telegram_id (uniq, null), locale, created_at
sessions         id, user_id, refresh_hash, device_name, apns_token (null), last_used_at, revoked_at
payout_methods   id, user_id, kind (card | phone), value, bank, label, is_default
                 «куда переводить мне» — видят только те, с кем есть общий счёт или долг

contacts         id, owner_id, name, phone (null), user_id (null), telegram_id (null)
                 «люди» владельца; user_id появляется, когда человек входит в Hamyon
                 или открывает вашу ссылку; telegram_id — когда нажал Start в боте как гость

bills            id, owner_id, title, currency, total, tip_percent, shared_amount, mode (equal | items),
                 payer_contact_id (null = владелец), version, seq, created_at, updated_at
bill_participants id, bill_id, contact_id (null = владелец), name, items_text («35 000 + 12 000»),
                 share, link_token_hash, paid_claimed_at, paid_confirmed_at, seq

debts            id, lender (user_id | contact_id), borrower (user_id | contact_id), created_by,
                 amount, currency, date, due_date, note, bill_id (null), status (open | closed), version, seq
debt_events      id, debt_id, kind, amount, actor_user_id, data (jsonb), created_at, seq
                 kind: created | payment_claimed | payment_confirmed | payment_rejected | edited | closed | reopened

notifications    id, recipient_user_id | recipient_contact_id, kind, payload (jsonb), channel,
                 dedup_key (uniq), status (pending | sent | failed | skipped), attempts, send_after, sent_at, error
tombstones       object_id, kind, seq, visible_to (uuid[]) — что удалено, для синхронизации
```

### Правила

- **Доли считает сервер** по тому же алгоритму, что `SplitBillView`: поровну, или «заказ + общее поровну»,
  затем разница со счётом (чаевые, обслуживание) — пропорционально заказу, с округлением до сума.
  Остаток от округления — на плательщика. Один набор тестовых примеров (JSON) гоняем и в Swift, и в Python,
  чтобы приложение показывало те же цифры, что и веб-страница.
- **История долга только дописывается.** «Сколько вернули» = сумма `payment_confirmed`. Лента в приложении
  (как сейчас в `DebtTimeline`) строится из событий — двух версий истории быть не может.
- Кредитор записывает возврат — он подтверждён сразу. Должник отмечает «Я вернул» — висит «ждёт подтверждения»,
  пока кредитор не подтвердит или не отклонит.
- Сумму и срок меняет только тот, кто создал долг; вторая сторона получает уведомление, правка остаётся в истории.

## 6. Синхронизация с приложением

- SwiftData остаётся главным хранилищем для экрана. У `Debt` появляются `remoteID`, `syncState`
  (local | pending | synced) и `version`.
- **Долги, которыми вы не поделились, на сервер не уходят.** Отправка — только по действию: «Поделиться с Азизом»
  или «Отправить счёт друзьям».
- Запись: обычные REST-запросы с UUID приложения; без сети — очередь в приложении, повтор при появлении сети.
- Чтение: `GET /sync?after=<seq>` — всё видимое пользователю с `seq` больше последнего полученного, плюс удаления
  из `tombstones`. Каждая запись в общие таблицы берёт `seq` из одной последовательности Postgres.
  Вызывается при запуске, при возврате в приложение, при обновлении свайпом и раз в несколько часов в фоне.
- Конфликты: события только дописываются — конфликтовать нечему. Правка полей долга с устаревшей `version` → 409,
  приложение перечитывает и показывает свежие данные.
- Два долга об одном и том же (у вас локальный «должен Азизу 50 000», Азиз прислал свой) — приложение предлагает
  «Это тот же долг?» по человеку, сумме и дате ±3 дня.
- **Автосверка по SMS** (на телефоне, сервер не нужен): пришёл перевод от Азиза на сумму его доли — приложение
  предлагает подтвердить возврат. Карты друзей из `payout_methods` помогают узнать получателя по последним цифрам.

## 7. Уведомления

Все уведомления — через таблицу `notifications`. Сервис пишет строку в той же транзакции, что и само действие;
Celery её отправляет и повторяет при ошибке. `dedup_key` (вид, объект, день) не даёт отправить дважды.

Канал для получателя выбирается так:

1. APNs — если у него Hamyon с пуш-токеном (только с платным аккаунтом);
2. Telegram — если он нажал Start в боте;
3. ничего — приложение показывает «Азиз ещё не подключён — отправьте ссылку».

| Событие | Кому | Текст и кнопки |
|---|---|---|
| Новый счёт | участникам | «Фаюлло: Ужин в Beshqozon. Ваша доля — 47 000 сум. Карта 8600 •••• 1234» · [Я перевёл] [Открыть] |
| «Я перевёл» | кредитору | «Азиз отметил, что вернул 47 000 сум» · [Пришло] [Не пришло] |
| Возврат подтверждён | должнику | «Фаюлло подтвердил: 47 000 сум получено» |
| Срок долга | должнику | в 10:00 по Ташкенту в день срока, второй раз — через 3 дня, дальше только вручную |
| «Напомнить» | должнику | вручную из приложения, не чаще раза в сутки |
| Новый долг от другого | второй стороне | «Азиз записал: вы должны 100 000 сум до пятницы» |

Кнопки в Telegram работают прямо в чате — приложение для этого не нужно. Бот пишет только тем, кто сам нажал
Start (правило Telegram), а `/stop` отключает уведомления.

## 8. Страница счёта для друзей без приложения

- `hamyon.uz/g/<токен>` — **ссылка для общего чата**. Список участников, «Кто вы?» — человек выбирает своё имя
  и попадает на личную страницу. Ошибиться можно, но среди друзей это не страшно: возврат всё равно подтверждает
  тот, кому перевели.
- `hamyon.uz/b/<токен>` — **личная ссылка**: что заказал, доля, карта получателя с кнопкой «Скопировать»,
  [Я перевёл], [Получать напоминания в Telegram] (`t.me/<бот>?start=p_<токен>` привязывает Telegram гостя).
- Страницы рендерит сервер (Jinja), на узбекском, русском и английском, с `noindex`. Токены — 128 бит,
  в базе только хэши, владелец может отозвать ссылку.

```

Люди
```

## 10. Безопасность

- **Кто из контактов в Hamyon — как в Telegram, но с ограничениями.** Приложение отправляет номера из
  контактов в `POST /contacts/match`, сервер отвечает только совпадениями. Список номеров не сохраняется
  (никакого «графа знакомств»), в логи не пишется. Найтись можно, только если в профиле включено
  «Меня могут найти по номеру» (по умолчанию — да, как в Telegram). Защита от перебора: не больше 3 000
  номеров за запрос и 5 сверок в сутки на аккаунт, новые номера сверх лимита — через сутки. Хэши номеров
  не помогают: всех узбекских номеров около миллиарда, их хэши перебираются за минуты, поэтому честнее
  слать номера по TLS и не хранить. Добавить человека можно и без этого — по ссылке, QR или общему счёту.
- Карты «для переводов мне» видят только люди с общим счётом или долгом.
- Токены ссылок и refresh хранятся как хэши; лимиты запросов в Redis — как у счётчиков QRTifact.
- Webhook Telegram принимается только с секретным заголовком.
- В логах нет телефонов и номеров карт. Ежедневный `pg_dump`, как в деплое QRTifact.
- **Ключ Gemini.** Сейчас он в приложении. Если раздавать Hamyon друзьям, ключ из приложения можно достать —
  тогда нужен прокси `/ai` на сервере с лимитом на пользователя (этап 4).

## 11. Что меняется в приложении

- **Страница профиля** — уже сделана без сервера (4 окт): фото, имя, телефон, «Куда переводить мне» (полный
  номер в Keychain), «Вы в выписках». С сервером добавятся статус Telegram, устройства, выход, удаление
  аккаунта и кнопка «Войти через Telegram».
- **Пригласить друзей** — уже сделано без сервера: контакты, выбор людей, отдельное сообщение каждому по SMS
  или в Telegram (`tg://resolve?phone=…&text=…`), отметка «приглашён». С сервером сверху появится раздел
  «Уже в Hamyon» из `/contacts/match`, а приглашение получит ссылку на бота.
- **Счёт с друзьями**: кнопка «Отправить друзьям» создаёт счёт на сервере и открывает «Поделиться» с общей
  ссылкой; у каждого участника виден статус: не открыл / открыл / перевёл / подтверждено.
- **Долги**: пометки «Азиз тоже видит», «ждёт подтверждения», кнопки [Пришло] [Не пришло] и «Напомнить».
- Синхронизация, токены в Keychain, очередь запросов без сети.

## 12. Этапы

> **Этап 1 (сервер) готов** — `~/hamyon-api`, 27 тестов. Не хватает бота, домена и выкладки на Timeweb,
> а в приложении — экрана входа.

| Этап | Сервер | Приложение |
|---|---|---|
| 0. Подготовка | домен, бот в BotFather, репозиторий, compose на Timeweb, CI/CD | — |
| 1. Аккаунт | вход через Telegram, профиль, карты для переводов, сессии, удаление | страница профиля и входа |
| 2. Общие счета | счета, участники, веб-страницы, уведомления в Telegram, «я перевёл» / «пришло» | «Отправить друзьям», статусы участников |
| 3. Общие долги | долги, история, `/sync`, напоминания по срокам | синхронизация, подтверждения, автосверка по SMS |
| 4. Платный аккаунт (если будет) | канал APNs, вход через Apple, прокси для ИИ | пуши, TestFlight для друзей |

Каждый этап полезен сам по себе: после этапа 2 можно делить счёт с друзьями, у которых нет приложения.

## 13. Решить до начала

- Домен (`hamyon.uz` свободен?) и имя бота.
- Платный Apple-аккаунт — определяет этап 4, остальное от него не зависит.
- Показывать друзьям полный номер карты для перевода (удобно) или только маску (тогда переводить будут
  по номеру телефона в Payme/Click). Рекомендация — полный номер: его и так отправляют в чат, но видят только
  участники общего счёта.
